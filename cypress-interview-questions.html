Top 10 Cypress Interview Questions and Answers (2026)

Cypress is a common choice for front-end and end-to-end testing, and interviewers often ask how it differs from Selenium. These questions cover its core ideas: automatic waiting, network stubbing with cy.intercept, fixtures, custom commands, and time travel debugging. Each answer gives the reasoning behind the feature, so you can explain when and why to use it.

1. What is Cypress?

Cypress is a JavaScript-based end-to-end testing framework that runs directly in the browser, making tests fast and easy to debug.

Why it matters in an interview: interviewers ask this to see whether you understand that Cypress runs inside the app's browser, which is why it behaves differently from WebDriver tools.

2. How is Cypress different from Selenium?

Cypress runs in the same browser as the app (no WebDriver), has automatic waiting, time travel debugging, and is limited to JavaScript. Selenium supports more languages and browsers.

Why it matters in an interview: a fair comparison names what Cypress does not support, such as multiple tabs and some cross-origin cases, rather than only its strengths.

3. What is the difference between cy.get() and cy.contains()?

cy.get() finds elements by CSS selector. cy.contains() finds elements by their text content.

Why it matters in an interview: choosing text-based selectors where the text is stable makes tests read like user behaviour and survive markup changes.

4. What is Cypress's automatic waiting?

Cypress automatically waits for commands and assertions to complete before moving on, so manual sleeps are not needed for most cases.

Why it matters in an interview: knowing that Cypress retries assertions, and when it does not, separates a tester who uses it correctly from one who adds waits everywhere.

5. What is cy.intercept()?

cy.intercept() is used to spy on, stub, or mock network requests and responses in tests.

Why it matters in an interview: it lets you test error states, such as a failed API call, without needing the real backend to fail.

6. What is a fixture in Cypress?

A fixture is a fixed set of data, such as JSON, loaded with cy.fixture() to use as test input, keeping test data separate from test code.

Why it matters in an interview: separating data from logic makes a suite easier to update when the test data changes.

7. What is the difference between cy.request() and cy.intercept()?

cy.request() makes an HTTP request directly from the test. cy.intercept() intercepts and controls network requests made by the app.

Why it matters in an interview: a common mistake is using cy.request() to test what the UI sends, when cy.intercept() is the right tool.

8. What are Cypress custom commands?

Custom commands are reusable functions added to Cypress with Cypress.Commands.add to avoid repeating code, such as a custom login command.

Why it matters in an interview: a login command used across many tests is a common example of reducing duplication in a real suite.

9. What is the difference between .then() and .should()?

.then() lets you work with the yielded value, like a callback. .should() makes an assertion and automatically retries until it passes or times out.

Why it matters in an interview: using .should() for checks rather than .then() is what makes Cypress tests stable.

10. What is Cypress time travel?

Time travel shows snapshots of the app at each command step in the Test Runner, letting you see what the app looked like before and after each action.

Why it matters in an interview: being able to explain how you debug a failing step with time travel shows practical experience with the tool.
